# A3 — Tacit-Objective Problems: When Code Can't Rescue Thinking

**Status: design doc v0.1, 2026-06-12. Hypothesis owner: Andrew (HYPOTHESES.md A3). Companions: C1_CINF_GAP.md (mechanism e), VARIATION_DIMENSIONS_LIT.md §5, A3_PROBLEM_BRAINSTORM.md (candidate families, delegated brainstorm).**

## 1. The hypothesis

Experiment 1's headline was that code rescues thinking: C0 23.8% → C1 95.0%, a 343:1 flip asymmetry. A3 conjectures a problem class where the rescue **fails** — problems whose evaluation knowledge lives in the model's weights and is laborious to serialize into a program, even though the model demonstrably possesses it. Canonical example: crossword fill. Ask the model "5-letter word meaning X starting with T?" and it answers correctly; ask it to write one program that fills the grid and the program has no lexicon to search with. The knowledge is *present but not exportable at reasonable cost*.

**The registered prediction (Andrew's):** on tacit-objective families, C1 lands closer to C0 than to C∞. Operationalized via the **rescue fraction** R = (C1 − C0) / (C∞ − C0), computed per family at calibrated difficulty: Experiment 1 families had R ≈ 0.94; A3 predicts **R < 0.5** for families with the property below. C∞ escapes because it is the only condition where model-resident knowledge can sit *inside* the search loop — code proposes and checks structure, prose supplies knowledge, alternating.

Why this matters more than the rest of the project: every Experiment 1 failure is patched by a REPL, so a skeptic can shrug — "fine, give the model a Python tool, problem solved." A3 is the regime where that patch fails on problems resembling real-world ones (the furniture-placement intuition), which is the actual argument that C0 capability — or a new architecture integrating computation with model-resident judgment — genuinely matters.

## 2. Membership test for the problem class

A family belongs in the A3 suite iff all four hold:

1. **Direct-query competence.** The model answers the individual knowledge units correctly when asked one at a time. This is measurable, and we measure it: every A3 family ships a **knowledge-probe sub-eval** (e.g., "is 'TARES' an English word?", "would placing a desk directly against a refrigerator be good design?") run on the same model. Target: probe accuracy ≥ 90% while the C1 condition fails. This dissociation — *knows when asked, can't deploy via code* — is the family's reason for existing, and it preempts the deflationary reading "the model just doesn't know the facts."
2. **Adaptive knowledge demand (sharpened 2026-06-12 by the brainstorm — criterion ii′).** Raw encoding burden is not enough: a C1 program has an escape hatch — the model can think of a candidate slice *while writing the program* (60 plausible words, 20 plausible cities), hardcode it, and let code do the filtering. Front-loading works exactly when the needed knowledge slice is nameable before search starts. The binding criterion is therefore that *which* knowledge units are needed depends on intermediate search state (crossing letters discovered mid-fill, strings enumerated from grid paths, a question revealed only by a deep computation). This yields a free within-suite control: matched family pairs with the same lexicon and verifier but front-loadable vs. adaptive demand (Spelling-Bee vs. Boggle in A3_PROBLEM_BRAINSTORM.md F6/F2) carry *opposite* rescue-fraction predictions — which immunizes A3 against "the model just didn't think to embed a wordlist." Quantify burden where possible (bytes of lookup table for a faithful program), and log hardcoded-candidate-list incidence in every C1 transcript.
3. **Rigorous verification.** Correctness remains checkable. Mechanical verification (best) keeps us inside the project's Phase-1 scoring rules; validated-rater verification (pairwise preference, inter-rater agreement reported) is acceptable only for the quarantined soft-scored sub-experiment (§4).
4. **Generability.** Procedural generation with parametric difficulty, like everything else in this project.

The crossword family satisfies all four: (1) clue-answering is a direct probe; (2) the generator's wordlist is tens of thousands of entries; (3) grid-match against the generator's list is mechanical; (4) grid size and wordlist obscurity are knobs.

## 3. Predictions (pre-registered for the A3 suite, 2026-06-12)

- **P1 (Andrew):** rescue fraction R < 0.5 per A3 family at calibrated difficulty (vs ≈ 0.9 for Experiment-1 families). The headline plot: R per family, Experiment-1 families clustered near 1, A3 families below 0.5.
- **P2:** knowledge-probe accuracy ≥ 90% at the same settings — the model has the knowledge it fails to deploy.
- **P3 (agent):** C1 transcripts show the failure mechanically: programs either omit the knowledge entirely (letter-frequency search, generic heuristics) or embed an impoverished from-memory snapshot (a 50-word lexicon where 5,000 words are needed). Instrument both: embedded-knowledge incidence and snapshot size/quality vs. the generator's resource. Pre-registered from H11: the model usually won't think to embed a wordlist (confidence 0.55).
- **P4 (agent):** C∞ transcripts show alternation as the winning pattern — candidate generation in prose, constraint propagation in code — and C∞ accuracy rises with the call budget (sweep 1/3/10/30), since each call is an opportunity to inject knowledge.
- **P5 (agent, the architectural claim):** superadditivity — C∞ > max(C0, C1) by ≥ 20 points at some difficulty band. C0 has knowledge without search; C1 has search without knowledge; only alternation has both.
- **P6 (agent, the criterion-ii′ validation, added after the brainstorm, still pre-run):** the matched control pair dissociates — the front-loadable family (Spelling-Bee-style, brainstorm F6) shows R > 0.7 while the adaptive family (Boggle-style, F2) shows R < 0.5, with the same lexicon, verifier, and model. If both are low instead, the deficit is candidate-generation breadth, not adaptivity — also informative, and the doc gets amended. Confidence 0.6.

## 4. The hybridization construction (Andrew's)

A general recipe for converting any formally hard problem into an A3 problem: **conjoin a formal constraint (mechanically scored) with a semantic side condition (model-resident knowledge required)**. Andrew's example: "find a short TSP tour whose drawn path looks like an animal, and say which animal."

The key design trick that keeps verification mechanical: **plant the semantic ground truth at generation time**. We don't ask raters whether the tour looks like a giraffe — we *generate the point set by stippling a giraffe silhouette* (TSP-art style, inverted), so the generator knows the hidden shape and "say which animal" has a checkable answer. Planted variants:

- **TSP-over-stippled-silhouette:** points sampled from a hidden shape's outline/interior; tasks range from "name the hidden shape" (recognition — checkable) to "find a tour ≤ L that traces the shape recognizably" (the full creative hybrid; recognizability scored by planted identity + a frozen-judge panel as secondary).
- **Maze-with-planted-path-shape:** generate the maze around a solution path that draws a letter or icon on the grid; "solve the maze, then say what the path draws."
- **Hidden-word structures:** permutation/assignment problems whose correct output spells planted words — though note: once the side condition is *exactly* checkable by string lookup against a disclosed dictionary, the tacitness leaks away; the semantic layer must stay model-resident (recognition, naming, plausibility), not table-checkable by the program.
- **Hard+soft text generation** (the inverted case — formal part is what code solves, tacit part is what the model solves): "write a coherent 6-sentence paragraph where sentence *i* begins with letter Lᵢ and contains exactly Nᵢ words." Counting constraints scored mechanically; naturalness scored by held-out raters with inter-rater agreement reported. This is the cleanest super-additivity (P5) candidate: Experiment 1 already shows the bare model fails counting; a program trivially passes counting but cannot emit natural text.

A note on honesty in framing: the hybrids are *creative tasks* — hard for LLMs and for humans (Andrew's observation: posing them is itself one). The planted-ground-truth trick buys mechanical scoring for the recognition/naming layer, but the full "make it look like an animal" objective will need the quarantined rater-scored track. Run hybrids as their own sub-experiment with both scoring layers, never pooled with the mechanical families.

Candidate families are now ranked in A3_PROBLEM_BRAINSTORM.md (eight families F1–F8 plus three planted hybrids H1–H3). Two upgrades it contributed beyond the ranking: the **planting trick generalizes** — pick the semantic label first, compile it into the formal instance, keep the label and a geometric mask as the answer key, so even "what does the tour depict?" scores mechanically (inverse TSP art appears genuinely novel; the forward direction is a mature practice, the inverse has never been used to test any solver); and a **new mechanism variant (e3): judgment downstream of execution** — C1 can run the decoder/renderer but is gone before the percept exists, so only C∞ ever *sees* what the computation produced. One calibration constraint the literature imposes: text-rendered shape recognition is weak in general (ASCII-art recognition benchmarks), so every hybrid's recognition probe must gate per model per label, or the family measures ASCII perception rather than the A3 property.

**Adopted build order** (from the brainstorm, endorsed): Boggle+Spelling-Bee matched pair first (cheapest build, carries P6), then the trapdoor-quiz hybrid (composition of two things already built, provable C1 ceiling), then crosswords (already planned as H11/R4), then inverse TSP art (the flagship figure), then trivia chains with the fact-table-size sweep (which turns encoding burden into a measured curve rather than an assumption).

## 5. Design pitfalls

1. **The callable-checker trap (Andrew's objection, conceded).** An earlier sketch proposed fitting an explicit scoring function to human ratings and keeping it "secret but used as verifier." As posed, it fails: if the checker is callable from the sandbox, a C1 program just embeds search-against-checker and the tacitness evaporates; if it's not callable and the function is arbitrary, the task degenerates into guessing hidden information (mechanism (f) — a query game, not tacit knowledge). The repair that survives: the verifier must be a *validated proxy for intuition the model already has* (membership condition 1), and it must live outside the sandbox in every condition. The model's access to the objective is through its weights or not at all; our access is through the generator's plant or through raters. Anything else measures the wrong thing.
2. **Wordlist disclosure is a knob, not a binding choice.** Disclosed-lexicon variants convert the family back into a formal problem (C1 should win — a useful within-family control proving the gap is the knowledge, not the search). Undisclosed is the A3 condition. Run both.
3. **Knowledge-probe / search-knowledge mismatch.** The probe must sample the *same* knowledge units the search needs (the actual words in the planted solution, the actual layout judgments in the scene), not generic neighbors — otherwise P2 doesn't license the dissociation claim.
4. **Judge contamination in rater-scored tracks.** If a frozen LLM panel scores naturalness/recognizability, the judge must be a different model family from the solver, and a human-agreement validation sample (~100 pairwise judgments) is mandatory before trusting it. Comparative (pairwise) judgments over absolute ratings, per the inter-rater literature.
5. **Calibration.** Like Experiment 1, every A3 family needs a difficulty band where C0 is low-but-nonzero and the knowledge probe stays ≥ 90%. If probe accuracy collapses at the same knob value as C0, the family is measuring knowledge limits, not deployment limits — re-knob it.

## 6. Positioning

The knowledge-coupling literature is recent and thin (VARIATION_DIMENSIONS_LIT.md §5: SweepClip, CrossWordBench, LR2Bench; C1_CINF_GAP.md §2.7: LLM-in-the-loop search, layout systems). Nothing in it: (a) runs a condition ladder isolating one-shot code from interactive code on matched instances; (b) measures the knows-when-asked vs. deploys-in-search dissociation with a paired knowledge probe; (c) treats the model-call budget inside the loop as the swept variable; (d) plants semantic ground truth to score creative side conditions mechanically. Those four are our additions, and P1's rescue-fraction inversion — if it lands — is the figure the architectural argument stands on.
